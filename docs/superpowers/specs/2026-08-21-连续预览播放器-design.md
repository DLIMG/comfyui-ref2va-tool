# Ref2VA 连续预览播放器设计

## 目标

在故事板表格上方增加一个连续预览区域，按当前故事板顺序连续播放各片段已经收集到网页结果库中的视频，方便检查剧情、节奏和镜头衔接。

本功能只负责网页内连续预览，不生成新的拼接文件，不调用 FFmpeg，不影响 ComfyUI 队列。

## 播放列表规则

1. 遍历当前故事板的 `shots`，顺序与表格一致。
2. 每个片段只取 `results` 中 `created_at` 最新的一个结果。
3. 没有可用结果的片段自动跳过。
4. 结果文件不存在或浏览器加载失败时，显示错误并自动尝试下一段，避免整条播放链中断。
5. 新结果被收集、结果被删除、故事板重新导入或片段顺序变化后，播放列表随下一次页面渲染自动刷新。

## 界面

连续预览区位于项目工具栏下方、故事板表格上方，默认展开，包含：

- 一个原生 HTML5 视频播放器，使用现有 `/api/results/video/{shot_id}/{result_id}` 地址；
- 当前片段标题与进度，例如 `02B 像潘旅长吗 · 3 / 8`；
- “从头播放”“上一段”“下一段”按钮；
- 已有结果数量提示；
- 没有任何结果时显示空状态，不渲染无效视频地址。

当当前视频自然播放结束时，自动切换并播放下一段；最后一段结束后停止，不循环。用户点击“从头播放”时回到第一段并开始播放。

## 数据与组件边界

- 后端不新增拼接或转码接口，继续复用现有结果视频接口。
- 前端新增纯函数构建连续播放列表，输入为 `board.shots`，输出为 `{shotId, title, result}` 项目数组。
- 播放器状态只保存在浏览器内，不写入 `storyboard.json`。
- 页面重新渲染时，若当前结果仍存在则保持当前条目；若被删除则切换到最接近的有效条目。

## 错误处理

- 视频加载失败：显示该片段加载失败，自动前进到下一条。
- 没有结果：显示“暂无可连续预览的视频”。
- 只有一个结果：仍可从头播放，上一段和下一段禁用。
- 所有结果均加载失败：停止自动前进，避免无限循环。

## 测试

- 按故事板顺序生成播放列表。
- 同一片段选择 `created_at` 最新结果。
- 跳过没有结果的片段。
- 处理缺失或无效 `created_at`，采用稳定的数组末项作为兜底。
- 播放结束自动前进，最后一段停止。
- 删除或新增结果后列表刷新且当前索引保持合理。
- 现有结果展示、提交、轮询和收集测试全部继续通过。

## 不在本次范围

- 不生成真正合并的 MP4。
- 不提供片段间转场、裁剪、音量归一化或字幕烧录。
- 不提供手动指定预览版本；固定使用每段最新结果。
